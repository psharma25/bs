Of the eight questions a compromise forces, this board answers the last and hardest: what produced this decision, and what else did that touch? The same seven stages twice, as they run today and as they should. Card colour is the trust zone, and everything else opens on demand.

STRETCHRegister each corpus in the catalogue with source, licence and a named owner.
Add three custom attributes to your catalogue's asset schema: licence, licence evidence link, and owner. Then make the ingest task fail when any is null. The fields are trivial. The hard part is deciding who owns a corpus assembled from four suppliers, and the answer that holds is the product owner who benefits from it, not the data engineer who moves it.
STRETCHAdd data suppliers to the vendor register you already run, same tiering questions.
Do not invent a second supplier process. Add one question to the existing onboarding form asking whether this supplier's material will be read by an AI system, and route a yes into the tiering you already use for software vendors. Two clauses are worth adding at renewal: notice if their data provenance changes, and notice if a corpus is withdrawn.

import hashlib, json, pathlib

def sha256(path):
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for chunk in iter(lambda: f.read(1 << 20), b""):
            h.update(chunk)
    return h.hexdigest()

def snapshot(root, source_uri, licence, owner):
    if not (source_uri and licence and owner):
        raise ValueError("refusing ingest: source_uri, licence and owner required")
    files = sorted(p for p in pathlib.Path(root).rglob("*") if p.is_file())
    manifest = [dict(path=str(p.relative_to(root)),
                     size=p.stat().st_size,
                     sha256=sha256(p)) for p in files]
    blob = json.dumps(manifest, sort_keys=True, separators=(",", ":")).encode()
    return dict(corpus_sha=hashlib.sha256(blob).hexdigest(),
                source_uri=source_uri, licence=licence, owner=owner,
                file_count=len(files), manifest=manifest)

                    if sp.get("color") == 16777215:            # white on white
                        findings.append((pno, "white text", sp["text"][:60]))
        layer = page.get_text().split()
        png = page.get_pixmap(dpi=200).tobytes("png")
        ocr = subprocess.run(["tesseract", "stdin", "stdout", "--psm", "6"],
                             input=png, capture_output=True).stdout.decode().split()

def canon(d):

def append(store, entry):

        claimed = body.pop("entry_hash")
        if body["prev_entry_hash"] != prev: return False
        if hashlib.sha256(canon(body)).hexdigest() != claimed: return False

    return True

THE ORCHESTRATOR YOU CAN BUILD AND HAND TO A COMPANY
One service, one command-line tool, and a set of thin adapters. It does not replace any scanner, harness or registry. It sits above them, turns each into a gate that emits a signed verdict, keeps the keys between the seven entities, and answers the two questions nothing on the market answers today: if this supplier is compromised which customers are affected, and if this record is challenged what produced it.
01The register
the seven entities and their keys
Corpus, index build, release, deployment, agent, tool call, decision record. Holds owner, tier and permitted actions, which no scanner and no identity product knows. Stores references and digests, never copies.
02Gate adapters
one thin wrapper per existing tool
Each adapter shells out to the tool the company already runs, normalises the result, and emits a signed verdict. Roughly 80 lines each. The tool stays theirs; only the verdict is yours.
03The ledger
append-only, hash-chained, write-once
Every gate verdict lands here under separate credentials, each row carrying the hash of the one before it. This is the part that turns claims into evidence, and the part that must not be editable by the pipeline.
04Write-back connectors
one per system of record
Writes the resolved chain onto the business record as fields, not attachments. One connector per system, priced separately, and the reason the chain survives an audit three years later.
05Two read-only agents
narrate and reconcile, never apply
An evidence narrator that walks the signed chain and drafts the audit story with every claim linked to an attestation, and a reconciler that explains breaks in plain language. Neither holds a credential that can change a control.
06What it is not
the discipline that keeps it sellable
Not a scanner, not a BOM format, not a tracing backend, not a GRC platform. Every one of those has incumbents. The register and the ledger have none.

SHOULD THIS BE AN AGENTIC AI WORKFLOW? THE ANSWER
No, not as the workflow. Yes, as workers inside it. The twelve steps above close every GAP 1 on the seven cards, the custody gaps, and they are all deterministic code. The GAP 2 items, the semantic ones, are not closed by that plan and need the AI-specific controls instead. That split is also the answer to whether this should be agentic.
The spine stays deterministic
Mint, carry, attest, ledger, land. No model call anywhere in it. If a model can author a custody record, you do not have custody, you have a narrative that sounds like it.
Gates are code, never agents
A gate earns its keep by being unambiguous and identical every run. An agent earns its keep on ambiguity. They are opposite jobs.
Agents go inside, read-only
Inventory discovery, tier proposals, evidence narration, drift explanation. Read, propose, explain. Never apply.
The one place agentic genuinely wins
Intake and triage of new AI use cases. Ambiguity-heavy, high-toil, verifiable, and a wrong answer costs a review rather than an incident.
Start with inventory
Discovery across unlike sources, high volume, low consequence per item, every claim checkable, and a miss costs a row the next run catches. Build this agent first.
Never let it run controls
Controls must be deterministic, diffable and replayable, which means code in a pull request. An agent may draft that request and explain the diff. It may not merge it.
The test to apply, every time. If the output has to be replayable and diffable in front of an auditor, it is code. If the output is a draft a named person signs, an agent may write it. A workflow you cannot replay is a workflow you cannot defend, and every step on this board ends up in front of someone eventually.
The red line, whatever you decide. No agent holds a credential that can modify identity policy, branch protection, continuous integration configuration, the tool allow-list, or the tier field. An agent that can change its own controls is a privilege escalation path by construction, however well it behaves.
