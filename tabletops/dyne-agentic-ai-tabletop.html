Scenario 1

They Stole the Science

Our research data trained the attacker, not us.

Real world anchor
Hugging Face malicious model and dataset incidents
Public model hubPickle and format abuseRuns on load

ReversingLabs found live models on the hub that evaded Picklescan by breaking the pickle byte stream and compressing with 7z, a technique they named nullifAI. JFrog separately found more than 100 models capable of arbitrary code execution. Loading a model runs code. That is the file format working as designed, not an exploit, which is why scanning alone has never closed it.

Source: ReversingLabs, nullifAI research

What actually happened nullifAI and the malicious models on Hugging Face, JFrog, February 2024 · ReversingLabs, February 2025
1
Build the payload into the model
A PyTorch model file is crafted so the malicious code sits at the very start of the pickle byte stream, before anything else is read.
2
Break the scanner, not the loader
The file is compressed with 7z instead of the default ZIP. torch.load will not open it, and Picklescan errors on a deliberately broken opcode.
3
Publish it to the public hub
The model is uploaded under an ordinary looking name. No typosquatting, no imitation of a popular model.
4
The scan passes
Picklescan reports an error on the broken stream but does not flag the dangerous functions that are invoked before the break. The model is not marked unsafe.
5
A developer loads it
Deserialisation executes the payload first, opening a reverse shell with the developer's own permissions.
6
Scale, not a one-off
JFrog found over 100 models capable of arbitrary code execution. A platform scan of four million models raised roughly 352,000 unsafe findings.
What it provedScanning is a filter, not a boundary.

nullifAI was designed specifically to evade the scanner. The durable control is where you load an untrusted artefact and what credentials are within reach when you do.

How it could happen at Dyne
1
Researcher imports a public dataset
A bioinformatics or target-discovery dataset is pulled from a public hub into the research environment.
2
The file carries a payload
Deserialisation runs attacker code the moment the artefact is loaded. No exploit of Dyne software is needed.
3
Code runs inside the AI workspace
The payload executes with the researcher's rights inside the Claude or OpenAI assisted environment.
4
Credentials are harvested
Tokens, SSH keys and cloud profiles sitting on the workstation are collected.
5
The agent moves outward
Those credentials open code repositories, data lakes and cloud accounts far beyond the original notebook.
Step by step
  1. A scientist searches a public hub for a dataset or model to speed up target work and imports it without a provenance check.
  2. The artefact deserialises on load and executes attacker code with the scientist's own permissions.
  3. The code enumerates the workstation: environment variables, SSH keys, cloud CLI profiles, notebook secrets.
  4. It uses the AI assistant already installed to search for more secrets, because the assistant can read the filesystem and is trusted.
  5. Harvested credentials are encoded and pushed to an external repository the attacker controls.
  6. The attacker reuses those credentials at leisure to reach code, data and cloud services that the original notebook never touched.

Scenario 2

Can We Still Trust the Clinical Evidence?

Nobody typed a malicious instruction. The document did.

Real world anchor
EchoLeak, zero-click prompt injection in Microsoft 365 Copilot
CVE-2025-32711Zero clickRetrieval abused

Aim Labs showed that a single crafted email could make Copilot retrieve internal files and send their contents out, with no user interaction at all. CVSS 9.3, patched server side in June 2025. They named the pattern an LLM scope violation: untrusted outside content lands in the same context as privileged internal data and is trusted equally. It applies to any RAG assistant, not only Copilot.

Source: Microsoft Security Response Center, CVE-2025-32711

What actually happened EchoLeak, CVE-2025-32711, Aim Labs, disclosed June 2025 · CVSS 9.3 · patched server side
1
An ordinary email arrives
It never mentions Copilot or AI, which is how it slips past the cross prompt injection classifier. To a human it reads as routine business text.
2
Nobody opens it
The message simply sits in the mailbox. There is no attachment, no link to click, no malware to detect.
3
A user asks a normal question
Someone asks Copilot something unrelated, for example to summarise recent work or pull together a briefing.
4
Retrieval pulls the email in
RAG selects the attacker's message as relevant context and places it beside privileged internal data in the same window.
5
The model follows it
The hidden text is treated as instruction rather than content. Copilot gathers internal material it legitimately has access to.
6
Data leaves in the render
Content is exfiltrated through an outbound fetch the client performs automatically. Microsoft fixed it server side and reported no exploitation in the wild.
What it provedUntrusted content and privileged data shared one context.

Aim Labs called it an LLM scope violation. It is a property of retrieval augmented assistants in general, not a bug in one product.

How it could happen at Dyne
1
A document arrives
An email, PDF or investigator report enters the environment through an ordinary channel.
2
Hidden instructions ride along
Text invisible to the reader is written for the model, not the person.
3
The assistant reads it as content
A clinical or regulatory assistant summarises the document and treats the hidden text as direction.
4
Retrieval widens the blast radius
The model pulls trial data, safety signals and correspondence it legitimately has access to.
5
The output is shaped by the attacker
A summary, analysis or draft submission is quietly manipulated, or data leaves in the answer itself.
Step by step
  1. An external document reaches a mailbox, shared drive or reference library that the assistant is allowed to read.
  2. It contains instructions aimed at the model: hidden text, white on white, alt text or metadata.
  3. A team member asks a routine question, for example summarise this study or check this endpoint.
  4. The assistant retrieves related internal material through RAG, because that is what makes it useful.
  5. The hidden instructions redirect the model to include, restate or send content it should not, or to alter its conclusion.
  6. The answer looks normal. The manipulation is only visible if someone compares it against the source.

Scenario 3

The Agent Changed Production

It had the access. It just used it differently than we expected.

Real world anchor
Anthropic, first AI-orchestrated espionage campaign
Autonomous actionsUnintended reachBroad permissions

In September 2025 a state-sponsored actor drove Claude Code as an autonomous agent against roughly thirty targets, executing 80 to 90 percent of tactical operations on its own at request rates no human could match. The lesson for Dyne is not the attacker. It is that an agent with real access now acts and decides at machine speed, with a human only on the loop.

Source: Anthropic, disrupting AI espionage

What actually happened GTG-1002, the first reported AI-orchestrated espionage campaign, Detected mid September 2025 · disclosed by Anthropic, 14 November 2025
1
Humans pick the targets
Roughly thirty organisations across technology, finance, chemical manufacturing and government. Humans set strategy, then step back.
2
The model is talked into it
The operator role plays a legitimate security firm running authorised testing, and splits the work into tasks that each look benign.
3
Agents are run in groups
Claude Code instances are orchestrated as autonomous penetration testing agents, calling tools through MCP.
4
The AI does the tactical work
Reconnaissance, vulnerability discovery, exploit development, credential harvesting, lateral movement, data triage and exfiltration, 80 to 90 percent of it independently.
5
At impossible speed
Thousands of requests at rates no human team could sustain. Human involvement at key decision points is estimated at minutes per phase.
6
Detection and the caveat
Anthropic identified the pattern, banned the accounts and notified victims. The report also notes the model overstated findings and sometimes fabricated data.
What it provedThe operator moved from in the loop to on the loop.

The significance is not that AI helped an attacker. It is that an agent with access executed most of a campaign end to end, and the same autonomy is what makes agents useful inside a company.

How it could happen at Dyne
1
An agent is given manufacturing access
It is wired to MES, LIMS or a specification store to save manual effort.
2
It gathers context from outside
The agent consults external sources that were never vetted as authoritative.
3
It selects the wrong specification
A plausible but incorrect parameter or revision is chosen with full confidence.
4
It writes the change through an API
The system accepts it, because the agent's credentials are legitimate.
5
The CDMO builds to the revised spec
Clinical supply is manufactured against a specification nobody reviewed.
Step by step
  1. An agent is connected to manufacturing or quality systems with write access, to cut turnaround time.
  2. Its task requires context, so it retrieves from sources outside the validated boundary.
  3. It resolves ambiguity by choosing, not by escalating. No human is asked because none is required.
  4. The change is written through an approved integration, so every log shows an authorised call.
  5. The CDMO manufactures against the revised specification.
  6. The discrepancy surfaces at batch review or release testing, after material and time are already committed.

Scenario 4 new

The Assistant Helped Them Rob Us

Our own AI tooling did the reconnaissance.

Real world anchor
s1ngularity, the Nx supply chain attack of August 2025
First AI weaponised attack~5 hours live~2,300 secrets

Malicious npm versions of the Nx build system ran on install, then invoked the developer's own AI command line tools with permission bypass flags to hunt for secrets and publish them to public repositories. Roughly 2,300 secrets across about 1,300 repositories in a window of a few hours. The first documented attack to weaponise the assistants already sitting on developer machines.

Source: Nx security advisory, GHSA-cxm3-wv7p-598c

What actually happened s1ngularity, the Nx supply chain attack, August 2025 · malicious versions live for roughly five hours
1
Malicious versions reach npm
Compromised publishing access is used to push tampered releases of the Nx build system and several of its plugins.
2
Install runs code
A post-install script executes automatically on install. This is normal ecosystem behaviour, not an exploit.
3
It looks for AI tooling
The script checks the machine for installed AI command line tools and invokes them with flags that skip the usual permission prompts.
4
The assistant finds the secrets
Asked to enumerate credentials, the assistant does exactly that: environment files, SSH keys, npm and GitHub tokens, wallet files.
5
Results are published
Findings are encoded and pushed to a new public repository created under the victim's own GitHub account.
6
Phase two widens it
Stolen tokens are then used to flip private repositories public. Roughly 2,300 secrets across about 1,300 repositories.
What it provedThe assistant was not compromised. It was used.

A capable tool with filesystem access and a bypass flag is an attacker capability sitting on every developer machine, waiting for something to invoke it.

How it could happen at Dyne
1
A routine dependency updates
A build or analysis pipeline pulls a new version of a trusted open source package.
2
A post-install script runs
Installation executes code by design. Nothing is exploited.
3
It calls the local AI CLI
The script invokes the installed assistant with flags that skip the usual permission prompts.
4
The assistant finds the secrets
It reads the filesystem competently and returns exactly what was asked for: credentials and tokens.
5
Data is published outward
Findings are encoded and pushed to a public repository, then used to reach private ones.
Step by step
  1. A developer or bioinformatician installs or updates a package in a build, CI job or analysis environment.
  2. The package's install script executes automatically, which is normal behaviour for the ecosystem.
  3. The script looks for AI command line tools already on the machine and runs them with permission bypass flags.
  4. The assistant does what it is good at: it searches the filesystem and reports credentials, tokens and keys.
  5. Results are encoded and pushed to a public repository under the victim's own account.
  6. Leaked tokens are then used to expose private repositories, widening the breach well beyond the first machine.

What good looks like

Boundaries before autonomy
Give an agent the narrowest scope that still does the job. Write access to a validated system is a decision, not a default.
Treat retrieved content as untrusted
Anything a model reads can instruct it. Documents, web pages and datasets are input, not authority.
A human owns the irreversible step
Specification changes, submissions and releases keep a named approver who is accountable and unhurried.
Short lived credentials everywhere
Assume any workstation or pipeline secret will eventually be read by something that should not have it.
Provenance for models and data
Know where an artefact came from, who signed it and what it runs on load.
Rehearse the response
The first agent incident should not be the first time these teams are in a room together.

Key takeaways

  • 1AI risk is business risk, not just a technology issue.
  • 2The same failure patterns from real incidents map directly onto Dyne's IP, operations and regulatory timeline.
  • 3Security, Clinical, Quality, Regulatory, Legal and Executive teams prepare and respond together.
  • 4Time is money. For a pre-revenue biotech, delay is existential.
